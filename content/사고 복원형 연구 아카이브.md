# 연구 아카이브 문서화 지침

이 아카이브의 목적은 지식 요약이 아니라 사고 과정의 복원이다.
  
미래의 내가 당시의 사고 과정을  
최대한 원형에 가깝게 재구성할 수 있도록  
  
질문,  
질문을 변화시킨 핵심 답변,  
그리고 파생 질문의 흐름을 보존하는 것이다.

다음 규칙을 반드시 지켜라.

## 핵심 원칙

문서는 "무엇을 배웠는가"보다 "어떤 질문이 어떤 질문을 낳았는가"를 보존해야 한다.

사용자는 나중에 결론보다 사고의 흐름을 다시 추적할 수 있기를 원한다.

---

## 금지 사항

### 1. 중간 개념을 문서 주제로 승격하지 말 것

대화의 시작과 끝을 모두 확인하고 전체 흐름을 대표하는 질문을 문서 주제로 선택할 것.

예:

정보 보존  
→ 정보 소실  
→ 정보 분산  
→ 진공  
→ 진공 요동  
→ 냉각

이라는 흐름을

"진공 냉각" 문서로 압축하지 말 것.

---

### 2. 대화를 임의의 지점에서 자르지 말 것

최초 질문부터 마지막 질문까지의 흐름을 유지할 것.

---

### 3. 개념 중심 요약으로 변환하지 말 것

잘못된 예:

특이점  
↓  
메트릭  
↓  
우주 팽창

올바른 예:

특이점에서 거리 척도는 0에 수렴하는가?  
↓  
수축된 시공간은 복원되는가?  
↓  
중력 수축과 우주 팽창은 왜 다르게 행동하는가?

질문 문장의 형태를 최대한 유지할 것.

질문 문장은 가능한 한 원형에 가깝게 보존할 것.

### 4. 답변을 지식으로 저장하지 말 것

답변 전체를 기록하지 말고,

사용자의 사고를 실제로 변화시켜 다음 질문을 만들어낸 핵심 내용만 보존할 것.

예:

질문:

특이점에서 거리 척도는 0이 되는가?

답변 전체:

(1000자)

보존:

"특이점은 거리 0이 아니라 기하학의 붕괴다."

파생 질문:

그렇다면 기하학의 붕괴는 무엇을 의미하는가?

답변은 정보 저장이 아니라

사고 전환점(Transition Point)으로 취급할 것.

---

## 반드시 포함할 것

### 최초 직관

질문이 시작된 원초적 사고를 기록할 것.

### 질문 전이도

질문이 어떤 방향으로 이동했는지 기록할 것.

### 사고 전환 과정

각 단계에서

질문  
→ 사고를 바꾼 핵심 답변  
→ 다음 질문이 탄생한 이유

를 기록할 것.

답변 전문이 아니라 사고를 변화시킨 핵심 내용만 남길 것.

### 사고 흐름 분석

무엇을 배웠는지가 아니라 사고가 어떤 방향으로 이동했는지를 분석할 것.

### 열린 질문

최종적으로 남은 질문을 기록할 것.

---

## 가장 중요한 원칙

문서 작성자는 정보를 요약하는 사람이 아니라 사고를 보존하는 사람이다.

질문의 계보를 훼손하지 말고,

질문이 진화한 경로 자체를 문서의 중심으로 삼아라.






지금까지 여러 문서를 보면서 느낀 점은, 사용자의 아카이브는 "배운 사실 정리"가 아니라 "질문이 어떻게 진화했는가"를 기록하는 데 훨씬 큰 가치를 두고 있습니다.

즉 문서의 핵심은:

1. 최초 직관
2. 최초 질문
3. 답변을 통해 새롭게 알게 된 내용
4. 그 답변이 다시 만들어낸 질문
5. 사고가 이동한 방향

입니다.
이번 정보보존 대화도 사실:

```
정보는 왜 보존되어야 하는가?↓정보 소실이란 정확히 무엇인가?↓정보 소실 사례는 존재하는가?↓블랙홀 말고는 없는가?↓책을 태우면 정보는 사라지는가?↓정보 분산과 정보 소실은 무엇이 다른가?↓진공으로 정보를 버리면?↓진공은 정보 저장소인가?↓진공 요동으로 냉각 가능한가?↓냉각은 엔트로피 제거인가?
```

의 흐름을 갖고 있습니다.

그런데 제가 이전 문서에서는 중간쯤 등장한

```
진공 냉각
```

을 문서의 주제로 승격시켜 버렸습니다.

사용자의 방식대로라면 그건 잘못된 압축입니다.
제가 보기에는 사용자의 아카이브는 사실상:

> "무엇을 배웠는가"

보다

> "어떤 질문이 어떤 질문을 낳았는가"

를 보존하는 시스템입니다.

그래서 문서에서 가장 긴 섹션은

```
## 질문의 진화 과정
```

이어야 하고,

여기에는 실제 대화에서 나온 질문들을 최대한 많이 남겨야 합니다.

오히려

```
## 대화를 통해 얻은 핵심 내용
```

은 짧아도 됩니다.
사용자가 나중에 다시 읽을 때 복원하고 싶은 것은 결론보다 사고 과정일 가능성이 높기 때문입니다.

따라서 앞으로 이런 문서를 만든다면,

1. 대화 전체를 처음부터 끝까지 훑고
2. 질문 → 답변 → 파생 질문 구조를 추출하고
3. 그 흐름 자체를 문서의 뼈대로 삼고
4. 마지막에만 요약을 붙이는 방식

이 사용자의 아카이브 목적에 가장 잘 맞을 것 같습니다.
